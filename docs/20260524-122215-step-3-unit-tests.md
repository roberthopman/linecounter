# ADR — Step 3: Unit-test the extracted pieces

- Date: 2026-05-24 12:22:15 UTC
- Status: Accepted
- Step: 3 of the gem-rebuild plan (see `docs/intention.md`)
- Follows: Step 2 — extract into require-able `lib/` (commit `83b4052`)

## Context

Step 2 created require-able seams. The golden master pins behavior at the CLI
boundary, but it is coarse: a failure says "something changed", not "which
piece". Before fixing bugs in step 4 we want fast, targeted tests on the
individual pieces so a future change points at the exact unit that moved.

## Decision

Add Minitest unit tests under `test/unit/`, one file per piece, and put `lib/`
on the test load path (`test/test_helper.rb`) so units can `require
"linecounter"` directly. The `rake test` task already globs
`test/**/*_test.rb`, so the new files are picked up with no Rakefile change.

Coverage added:

```
test/unit/branch_analyzer_test.rb     keyword + operator counts; all keys present
test/unit/scanner_test.rb             loc edge cases; ruby_files excludes schema.rb
test/unit/structure_analyzer_test.rb  statement_span continuations; counts by type/visibility
test/unit/git_test.rb                 parse_since: nil/blank/passthrough/today/relative/case
test/unit/analyzer_test.rb            aggregation sums; sort order; min-loc filter; schema exclusion
```

## Pin current behavior, including known bugs

Consistent with the project's pin-now-fix-later philosophy, unit tests assert
**current** behavior, not desired behavior. The most important example:

- `structure_analyzer_test.rb#test_counts_pins_def_self_and_initialize_double_count`
  pins that `def self.x` and `def initialize` are *also* counted as plain
  public instance methods (they match `DEF_RE`). The test is labelled as a
  pinned known bug.

When step 4 fixes this, that unit test will change deliberately — the same
signal the golden snapshots give at the CLI level, but localized to the unit.

For aggregation, tests assert the *relationship* (overview == sum of per-file
counts) rather than brittle magic numbers, so they stay meaningful as fixtures
evolve.

## Notes

- `Analyzer`/`Scanner` tests reuse `RepoBuilder` to get a deterministic git
  fixture; pure pieces (`BranchAnalyzer`, `StructureAnalyzer.statement_span`,
  `Git.parse_since`) need no git.
- `parse_since` relative-form tests use `assert_in_delta` (5s) because they
  depend on `Time.now`.
- Gotcha recorded: a private test helper named `run` shadows Minitest's own
  `run`; the analyzer test helper is named `analyze` instead.

## Result

32 tests green (8 golden + 24 unit). No production code changed in this step.
